# 给台式机 Codex 的提示词（整段复制即可）

请接手当前目录中的 ReasoningRL Lab 项目。我的目标是大模型算法相关实习，研究小模型数学推理的 SFT → GRPO，以及相同计算预算下均匀采样与动态难度采样的差异。这个项目由我的 RTX 3060 Laptop 6GB 笔记本迁移而来；这台台式机配有 RX 9070 XT，但请先实查，不要假定环境已经可用。

先阅读当前目录的 AGENTS.md、README.md、PROJECT_CONTEXT.md、HANDOFF.md、docs/HARDWARE_AND_BUDGET.md、docs/PROTOCOL.md。若通过GitHub克隆，记录git commit并检查工作树；若通过离线包迁移且存在migration/TRANSFER_MANIFEST.json，先运行 `python scripts/verify_transfer.py`。只在本项目目录内操作，不修改其他项目；使用项目自己的虚拟环境、缓存、数据和检查点。

1. 检查实际操作系统、Python、GPU、驱动、可用显存、RAM、磁盘及已有 ROCm/PyTorch。核对 AMD 官方 Radeon 支持矩阵及安装文档，必须区分原生 Windows、WSL 和 Linux，不把笔记本 CUDA 配置复制到 AMD。交接文档核实过 ROCm 7.2.1 的受支持组合，但你必须结合这台机器复核；PEFT/TRL 的 Python 依赖兼容不代表 AMD 官方认证。
2. 以官方支持的 PyTorch ROCm 轮子为底座，建立项目内独立 `.venv`。然后安装 `requirements/common.txt` 及本地项目（无额外依赖安装）。AMD 首轮使用 `--hardware rocm`：FP16、非量化、SDPA、AdamW、单卡，不安装 CUDA bitsandbytes、flash-attn、vLLM，不先改系统驱动或重启。若需要系统级操作，说明具体必要条件后再由我处理。所有自动下载仅限公开免费模型和数据，不使用付费 API，不租卡。
3. 继承已经固定的数据文件与 manifest，先核验哈希和测试。不要重新随机划分，不阅读测试题、答案或预测来选模型、调参或设计采样。官方测试集和 SVAMP 在协议冻结后才允许最终评测；初始跨集重复审计仅作一次数据卫生检查，不提供模型表现。
4. 根据 models.lock.json 下载同一公开模型检查点，优先 Qwen3-1.7B（已后训练，不能写成 Base）。先运行 hardware 和 check-model，验证前向、反向、非零且有限梯度、仅 LoRA 更新、保存与重载。若 FP16 有数值问题，记录原因，使用官方支持的精度另建明确配置，先验证再训练。
5. 查看 HANDOFF.md，继承已经完成的笔记本结果；它们只证明笔记本上的相应阶段，不能写成台式机验证。由于硬件和精度变化，应在台式机重跑原模型验证集基线与 SFT，不能把笔记本 NF4 结果和台式机 FP16 结果直接当作采样收益。台式机 C/D/static 从同一个台式机 SFT 检查点开始。
6. 按数据与评分器 → 公开模型验证集基线 → LoRA SFT → 均匀 GRPO → 动态与静态采样 → 对照的顺序，跑一个种子短预实验。确认奖励确有变化、组内优势/梯度正常、动态权重真实更新，记录速度、长度、截断、格式错误与显存。根据实测速度缩放 pilot/main；不要未经验证就运行大规模任务。
7. 核心对照用共同的实际时间预算，并把初始难度探测、动态更新及验证计入成本；保留 token 细分、device elapsed、wall time、显存。不能只比较相同步数。正式 C/D 至少三种子（13、29、47），预算不足就说明实际次数。main 配置目前是容量上限草案，冻结前需根据 pilot 速度确定。测试集不用于选检查点或调参；冻住具体协议与检查点后再最终独立评测。
8. 结果没有提升就保留，不以 loss 下降声称泛化提高。分别更新“已实现、已冒烟验证、已完成真实训练、已完成正式对照”。原始预测、日志、检查点、指标、图表和误差审阅都保存在本目录，持续更新 HANDOFF.md、PROJECT_CONTEXT.md 和实验报告。

本机已有的重要发现需要继承：少量题与相同步数结果不支持泛化或同预算优势；早期G2全组零方差未更新；部分负奖励只来自最终答案区域/重复/截断。TRL0.23.1在NVIDIA 4-bit BF16路径会再次转换embedding/head精度，训练内验证仅作诊断，比较终点须独立重载。扩大本机pilot把SFT池与GRPO池分开，并为最终验证预留预算；不要覆盖其旧配置或把不同阶段结果混成一次受控实验。先在1.7B完成三种子受控结果，3–4B可作为后续独立规模研究，不能假定换卡必然提分。

直接开始检查和可执行工作，不停在规划。遇到不可访问的机器或确实缺少的算力，完成可复现训练包并给出证据边界。不要修改简历或声称新算法。
