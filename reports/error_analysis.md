# 开发预实验的失败案例与误差分析

以下只使用固定验证集和训练题，未启用GSM8K官方测试或SVAMP。案例归因为Codex结合题目、标准解与原始输出所做的模型辅助核查，**尚未由用户人工复核**。

## 1. 评测协议与实现问题

最初 `math_numeric_v1` 在提示中直接出现 `<numeric answer>` 占位符，模型多次原样复制。另有Transformers4.57.1的model-default合并，把预期greedy改成模型默认采样。这一轮A输出保存在 `runs/local17_20261105_smoke-A`，`invalidated.json` 明确排除其作为有效基线。修正为v2自然语言指令，并显式 `use_model_defaults=False, do_sample=False`；增加了真实库行为的回归测试。

扩大预算实验启动后，训练池审阅发现`gsm8k-train-05134`的题干“Jared比Ann少15%”与参考解“Ann=Jared*1.15”不一致。按字面应为`Ann=300/0.85`、`Alfred=Ann-7`，总数`16981/17`且汽车数量非整数；不能自行用四舍五入给出另一个整数标签。官方原始train第5135行即如此，原始数据及本轮983奖励目标均保留，见[training_label_audit.json](training_label_audit.json)。这是模型辅助核查而非人工裁定。本轮8题池中此项占1/8；其曝光与奖励需单列，不能将拟合有疑义标签解释成数学能力改善。后续清洗另立训练信息规则、另冻对照，不在当前C/D/E中途换题或改gold。

v1评分器只读####所在行，误把下一行 `**Answer:** 864` 等明确答案算成提取失败。`numeric_final_v2` 接受最终答案区域中唯一无歧义数值，严格格式统计不变。A/B的原始预测和原指标均保留；通过 `scripts/rescore_validation.py` 在验证集离线重评分，无重复模型生成，审计链在 `rescoring_audit.json`。该校准发生在任何保留评测之前。

首次TRL GRPO生成遇到 `expected scalar type Float but found BFloat16`：k-bit准备后的冻结层含FP32，而unwrap后的生成没有保留所需autocast。显式在生成评分阶段进入共同AMP上下文后修复。失败原始日志在 `logs/local17v3_20261105_C_s13.log`，不计作成功训练。

## 2. 零方差不等于学会

最初4步均匀GRPO（G=2）奖励均值0.75，组内零方差比例100%，非零优势数0，LoRA delta L2=0。尽管训练调用成功且保存了检查点，参数没有学习更新。该结果保留在 `runs/local17v4_20261105_C_s13`，后续扩大组大小与题池进行信号预实验。

这个C检查点的adapter文件SHA256与B完全一致。独立重载C后的8题输出与B逐字一致，见 `evaluation_context_check.json`。训练上下文中的验证输出与独立重载有差异，因此训练内验证只作诊断曲线；A/B和正式终点统一走独立重载评测，不能把上下文差异解释为参数提升。

## 3. 具体数学错误：B的两道错误

|验证题ID|实际输出错误|正确建模|辅助归因|
|---|---|---|---|
|gsm8k-train-05654|把每个工作日15分钟、每个周末日30分钟写成 `(15+30)*5=225`|`15*5+30*2=135`|周末与工作日的数量条件处理错误，乘法本身正确|
|gsm8k-train-00065|按一次草坪收费33元加3次10元小费，得到63|每周16个草坪：`33*16+10*3=558`|遗漏16个草坪条件|

完整题目、原始输出与审核字段位于 `runs/local17v2_20261105_smoke-B-val/validation/error_review.jsonl`。这里没有把“最终数值错误”统一标成算术错；两例均有明确的条件遗漏/建模证据。

A中的 `gsm8k-train-00848` 在可见推导中得到24，但192-token预算结束时最终答案区域未写完；B在同一解码预算下输出完整24。它属于本次观测到的长度/截断差异，不足以证明普遍推理能力提高。

## 4. 当前可解释范围

扩大SFT的同32题/256-token开发评测中，A22/32、B19/32。B严格格式错误从A的75%降至43.75%，但截断从3/32升至8/32，正确率更低；格式改善和loss下降均没有转化为本次开发正确率收益。逐题配对有7题由对变错、4题由错变对，记录在`enlarged_sft_paired_transitions.json`。这是开发结果，不作泛化推断，也不把不同训练量/解码上限的前一轮8题混为一次实验。

新增两例辅助审阅（human_reviewed仍为false）：gsm8k-train-00848把“每6头牛每周108升”当作“所有牛每周108升”，算出4个六牛组后直接回答4头，遗漏乘6；其可见除法正确。gsm8k-train-00560从每箱18元开始不断翻倍，未用48箱这个条件，最终截断；不能仅将其归为提取失败，重复计算与条件使用错误同时存在。对应B的error_review.jsonl保留明确assistant_review字段。

进一步审阅了3个未截断但数值错误的扩大B输出。gsm8k-train-03931把第一天Tom的5球代入第二天Gina的计算，写成5-2=3，属于日期条件错配；gsm8k-train-04580把净亏30元建模为`-2*y=-30`，遗漏获胜收入，应联立`x+y=60`与`x-2*y=-30`，属于收益建模错误。gsm8k-train-01534把104本书当成百分比，未使用35%的儿童书占比，并声称`104*0.8996=92`（实际93.5584），同时出现建模与可见算术错误；正确计算为`104/0.65=160`。这3例同样仅作模型辅助审阅，未标成人工确认。

后续首轮G=4、8步、seed13完成：共同独立重载的C5/8、D6/8、E5/8。D的总GRPO时间843.74秒，其中探测595.53秒；C359.95秒，E447.55秒，不能用相同步数解释为成本公平。D/E初始探测原始文件逐字节一致；D在step4刷新前的4步梯度均为0，刷新权重变化不能解释为此前训练获得能力。

C的2个、D的1个、E的3个负奖励rollout均可见正确的中间数值，但最后答案区域为空、重复结束标记或被截断。例如D在推导中得到22，最终区域在本轮192-token上限处只输出数字2；评分器如实将最终2判错。E两例形如`#### 40 ####`、`#### 14 ####`，最后一个显式标记为空。保留这些原始记录，不为当前结果再次改评分器；它们主要说明输出控制问题，不能当成数学算法收益。

TRL精度转换经实际加载验证：embedding和lm_head从FP32变成BF16，LoRA/norm保持FP32。`reports/trl_precision_audit.json`定位了训练内验证与独立重载不等价的一个具体来源。共同独立终点采用相同加载精度，训练内指标单列。

在同8道开发验证题上，独立重载后的A为5/8，B为6/8；两者严格格式错误率均75%，A有1道截断、B没有。该样本非常小，又参与提示与评分器开发，不能把多对1题表述成泛化提升。SFT仅实际训练4个optimizer step，训练池32题；不把32题池说成32题都已训练。

后续对照应继续记录奖励稀疏、组内方差、探测开销、动态权重、运算/长度特征曝光，以及独立重载后的固定评测。正式多种子、保留测试与迁移结果尚未完成时，保留空缺，不补造数字。
